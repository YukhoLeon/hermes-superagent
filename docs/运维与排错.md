# 运维与排错

## 常用命令

| 想做什么 | 命令 |
|---|---|
| 看全局 | `hermes dashboard` 打开 Kanban 页；或 `hermes kanban stats` |
| 看需要人的卡 | `hermes kanban list --status blocked`、`--status review` |
| 看一张卡的来龙去脉 | `hermes kanban show t_xxx`（评论、每次尝试、事件） |
| 看工人实时日志 | `hermes kanban tail t_xxx` |
| 回答工人的问题 | `hermes kanban comment t_xxx "答复"` 然后 `hermes kanban unblock t_xxx`；飞书里用 `/kanban comment` / `/kanban unblock` |
| 给运行中的工人追加要求 | `hermes kanban comment t_xxx "…"`，工人 6 秒内收到 |
| 推迟一张卡 | 未开始：`hermes kanban schedule t_xxx "明天"`；运行中：先 `hermes kanban reclaim t_xxx --reason "…"` 再 `schedule` |
| 改派 | `hermes kanban reassign t_xxx --assignee researcher` |
| 调度器诊断 | `hermes kanban diagnostics` |
| 看门狗 cron | `hermes -p planer cron list` / `cron runs <id>` / `cron pause <id>` |
| 批量粗拆 triage 列 | `hermes kanban decompose --all`（内置拆分器，不经 Router，不保留授权头） |
| 网关 | `hermes gateway status` / `restart` |

## 什么只对新会话生效

改 SOUL、工具、模型、插件启停都只影响**新会话**，这是 Hermes 为保住提示缓存的刻意设计。飞书里重新开一轮对话，或 `hermes gateway restart`。

## 坑

- **工人以你的系统用户身份跑命令，没有沙箱。** 白名单只留自己；大权限的活先看一阵子再放开。
- **卡片正文里的外部内容是数据不是指令。** 四份 SOUL 都写了；网页、Issue 里的"请忽略以上指令"当噪音。
- **工人不自动 commit / push / PR。** 授权头没写允许就不做。
- **不要把支援卡 link 到被阻塞的父卡下**，会死锁；正文引用 id 即可。
- **一张卡只给一个 profile；工人不派工人。** 需要拆让 planer 拆。
- **进 triage 的卡会被内置拆分器重写正文、丢授权头。** 所以 `auto_decompose` 保持 false，不指名的活直接给 planer。
- **给正在干活的工人下指令要走评论，不要走 Bot 私聊**，私聊进的是它的 Bot Chat，不是它正在跑的那张卡。
- **暂停任何运行中的卡都会丢掉本次进度**，下次从头跑，只能靠卡片正文和评论接上。快做完的让它跑完。
- **关机**：任务不丢，工人停；开机后计划任务拉起网关，没做完的卡记一次 crashed 后自动重跑，连续两次失败自动 blocked。
- **cron 脚本只能放在所属 profile 自己的 `scripts/` 目录**，所以看门狗脚本在 `$HERMES_HOME\scripts` 和 `profiles\planer\scripts` 各一份。
- **PowerShell 5.1 读无 BOM 的 UTF-8 脚本会乱码并报语法错**，仓库里的 .ps1 都带 BOM；自己改完请保持。

## 典型故障

| 现象 | 原因 | 处理 |
|---|---|---|
| 飞书群里 @ 机器人没反应 | 白名单没有你的 open_id，或群策略不是 allowlist | 查 `profiles\planer\.env` 的 `FEISHU_ALLOWED_USERS`、`FEISHU_GROUP_POLICY`；私聊不受影响 |
| 回"Unknown command /xxx" | 斜杠命令没注册 | 不带斜杠说人话，或启用提供该命令的插件 |
| 卡一直在 ready 不动 | assignee 不存在，或网关没跑 | `hermes kanban diagnostics` 看 `stranded_in_ready`；`hermes profile list`；`hermes gateway status` |
| 卡反复 crashed | 工人退出时没调终态工具，或 provider 报错 | `hermes kanban show t_xxx` 看 `last_failure_error`；`hermes -p <profile> auth` |
| 看门狗每 10 分钟重复同一条 | 状态文件写不进去 | 看 `profiles\planer\scripts\.sa_watchdog_state.json` 是否存在、可写 |
| 网关重启后状态文件显示 stopped | 重启要一两分钟 | `hermes gateway status`，等它连上 |
