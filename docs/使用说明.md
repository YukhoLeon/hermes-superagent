# Hermes Super-agent 使用说明

> 面向使用者的说明。不讲原理，只讲"怎么用、会发生什么、出问题怎么办"。

## 它是什么

一个在飞书里就能使唤的"项目调度员加几个专职工人"。你说一句要做什么，调度员把它拆成任务卡、派给合适的工人，工人在后台干活，做完了主动告诉你。中间不需要你盯着。

- **Planer**：调度员。只负责接活、拆活、派活、汇报，自己不动手。
- **Researcher**：查资料、做调研、核对事实、写报告。
- **Coder**：写代码、跑测试、修 Bug。
- **Reviewer**：审查代码和交付物，把关质量。
- **看板**：所有任务都是看板上的一张卡，谁在做、做到哪、卡在哪一目了然。

## 怎么派活

在飞书里对 Planer 说人话就行，不需要记命令。

```
帮我调研一下三家云厂商的对象存储价格，出一份对比表
```

```
登录页报 500，帮我查一下原因并修掉
```

Planer 会回一句话确认，告诉你建了哪张卡、派给了谁，然后就安静了。这是正常的，它不会汇报过程。

说得越清楚，结果越准。好的说法包含三样东西：**要什么、给谁用、什么算做完**。

```
写一份 sa-gate 的使用说明，给第一次用的同事看，一屏以内，带一个可以直接复制的例子
```

## 什么时候会收到消息

只有三种情况，其余时间它不打扰你：

| 收到什么 | 意味着什么 | 你要做什么 |
|---|---|---|
| **完成通知** | 工人做完了，附一句结果和产物位置 | 看一眼，满意就完事 |
| **提问** | 工人遇到必须由你决定的事（花钱、删东西、方案二选一、缺资料） | 回答它，见下一节 |
| **看门狗提醒** | 有事挂了很久没人处理，或有任务疑似卡死 | 按提示处理，或告诉 Planer 怎么办 |

一切正常的时候，它一个字都不会发。没消息就是好消息。

## 工人问你问题时怎么回答

工人提问时会带上卡号（形如 `t_1a2b3c4d`）。最简单的方式是直接告诉 Planer：

```
t_1a2b3c4d 那张卡，用顺丰，其他不变，继续
```

Planer 会把你的答复写进卡里并让工人继续。你也可以在飞书里直接敲命令：

```
/kanban comment t_1a2b3c4d 用顺丰
/kanban unblock t_1a2b3c4d
```

## 中途改要求

任务还没做完，想追加或修改要求，直接对 Planer 说，记得点名是哪件事：

```
那个 1688 的比价任务，某某商品一定要顺丰
```

- 任务还在排队：工人开工时会看到。
- 任务正在做：工人几秒内就会收到，当场调整。
- 任务已做完：Planer 会另建一张后续卡，接着上次的结果做。

## 看进度

| 想看什么 | 怎么看 |
|---|---|
| 全局一眼看 | 电脑上运行 `hermes dashboard`，打开 Kanban 页 |
| 问 Planer | 飞书里问"现在有哪些任务在跑" |
| 某张卡的详情 | `hermes kanban show t_xxx` |
| 工人实时日志 | `hermes kanban tail t_xxx` |

## 暂停和恢复

对 Planer 说即可：

```
今天别再派新活了，正在做的让它做完
```

```
明天早上九点恢复
```

```
t_1a2b3c4d 先放一放，下周再说
```

被暂停的卡进"Scheduled"列，不算出错，不会有人催你。

## 什么事它不会自己做

这些都需要你点头，工人遇到了会停下来问：

- 花钱、付款、下单
- 删除数据、删除文件
- 对外发消息、发邮件、发帖
- 提交代码、推送、合并、开 Pull Request
- 需要做取舍的设计决定

## 常见问题

**它没回我。**
先看是不是群聊：群里必须 @ 它，而且发言人要在白名单里。私聊不受限制。

**它回了"收到"之后一直没动静。**
正常。工人在后台干，做完才通知。想看进度就问它，或者打开看板。几小时还没结果，看门狗会主动提醒。

**它说"需要你决定"，可我不想管这么细。**
回它一句"你看着办，按最省事的来"即可，它会把这句话记进卡里。

**我说错了，想撤回任务。**
对 Planer 说"把 t_xxx 那张卡取消掉"。

**电脑关了会怎样。**
任务不会丢，但工人会停。开机后系统自动恢复，没做完的卡会重新开始做。

**它做错了怎么办。**
在飞书里告诉 Planer 哪里错了，它会建一张返工卡。所有卡都有完整记录，随时可以追溯"当时是谁要求的、工人做了什么"。
